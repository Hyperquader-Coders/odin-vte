# Spec — odin-vte

## Packages

```
vte/   package vte: generated by runic from vte/rune.yml, plus patched.odin (pins)
       and helpers.odin (hand-written, never regenerated)
```

Import through the `vte` collection: `import "vte:<package>"`.

## Surface

The headers are those of `vte-2.91-gtk4`: `vte.h` and what it includes, among them
`vteterminal.h`, `vtepty.h`, `vteregex.h`, `vteuuid.h` and the termprop API.

Every public declaration of the bound headers (VTE 0.84.1), named as runic names
them, plus the hand fixes in [PATCHED.md](PATCHED.md). Deprecated API is bound, because
`GLIB_DISABLE_DEPRECATION_WARNINGS` is set when generating.

## Hand-written: `vte/helpers.odin`

Not generated; `make generate` leaves it alone.

- `connect_<signal>(terminal, handler, data = nil) -> glib.ulong` for every `VteTerminal` signal
  (`-` is `_`), over `gobject.signal_connect`. The callback types follow the C signatures,
  the instance first and `user_data` last: `Notification_Proc` (no parameters),
  `Child_Exited_Proc`, `Commit_Proc`, `Char_Size_Changed_Proc`, `Resize_Window_Proc`,
  `Move_Window_Proc`, `Hyperlink_Hover_Uri_Changed_Proc`, `Setup_Context_Menu_Proc`,
  `Termprop_Changed_Proc` and `Termprops_Changed_Proc`. The tests compare every one with the
  loaded library's signal list.
- `PCRE2_*` as `u32` constants, with the values of `pcre2.h`: the compile flags, the extra
  compile flags, the JIT flags and the match and substitute flags that the regex API takes.
  Flags VTE refuses or does not pass (`PCRE2_SUBSTITUTE_OVERFLOW_LENGTH`, the DFA, convert and
  error codes) are not defined. `REGEX_FLAGS_DEFAULT` is the generated one.

## Version

The binding records the library version it was generated from. `make test` compares it
with the version macros of the bound headers and the loaded library (DECISIONS §3).
