# Decisions — odin-vte

Settled choices. An entry that stops being true is rewritten, not appended to.

## 1. Generated, not hand-written

The bindings are generated with runic from the headers Amber ships, so a library bump is a
regeneration. Hand fixes are the exception and are tracked in [PATCHED.md](PATCHED.md).

## 2. One package, `vte`

All of the VTE headers are bound as one package, `vte`, imported as `vte:vte`. The GTK types
it uses (`Widget`, `WidgetClass`, `Renderer`) come from odin-gtk4 and are never redeclared.

## 3. The version test and the loaded library

The bound version is 0.84.1, the VTE that the amber-vte package builds. The distro's libvte is
0.76.0. The test treats them as follows:

- the header macros must equal the README's `**Bound version:**` line, always;
- the loaded library must have the same major version and a minor of at least 0.76;
- when amber-vte's build is staged, `make test` links it, puts it on `LD_LIBRARY_PATH`, sets
  `VTE_BUNDLE_EXPECTED` and defines `VTE_BUNDLE`; the loaded library must then be 0.84.1
  exactly, and the termprop API (0.78 and later) is called. A wrong path fails the test; it does
  not fall back to the distro's library.

Rejected: requiring the exact version everywhere, which fails on a machine without the bundle
built; and calling the termprop API unconditionally, which does not link against 0.76.

## 4. The licence is LGPL-3.0-or-later throughout

Every bound header carries the LGPL notice ("version 3 ... or (at your option) any later
version"); `vtetypebuiltins-gtk4.h` is generated by glib-mkenums under the licence of the
project. No header bound is GPL-only. VTE's GPL-3 files (`COPYING.GPL3`) are implementation
sources under `src/`, which are not bound. `LICENSE` is the text of upstream's
`COPYING.LGPL3`.


## 5. Flag enums are bit_sets, chosen by a list

The GFlags types (`PtyFlags`, `UuidFormat`, `PropertyFlags`) and `FeatureFlags` (a `guint64`
flag set with no GType) are `bit_set[FooBit; u32]` (`u64` for `FeatureFlags`), as in odin-gtk4
(its DECISIONS §5): `{.NO_HELPER, .NO_CTTY}`, with the C size and bits. `postprocess.sh` rewrites
them from a list, because a value rule cannot tell them from sequential enums. The list is
the `g_flags_register_static` entries of `vtetypebuiltins` plus `FeatureFlags`. `WriteFlags`
(registered as an enum, one zero member) and `Format` (one of two values) stay enums, as do
`CursorBlinkMode`, `TextBlinkMode`, `PropertyType` and the rest. Generation fails if a listed
enum is missing, negative or has no single-bit member; a new GFlags type in a header bump is added
to the list by hand. `UuidFormat` is a GFlags type although a call passes one format:
`{.SIMPLE}`, and `UUID_FORMAT_ANY` for the parser.

## 6. Signal helpers and PCRE2 flags are hand-written

`vte/helpers.odin` holds the typed `connect_<signal>` helpers and the `PCRE2_*` constants. Neither
comes from a header runic reads: VTE declares its signals as class vfuncs and in
`g_signal_new` calls, and leaves the PCRE2 flags to `pcre2.h`. The constants are `u32`, the type
of the `guint32` flags parameters, not bit_sets: callers combine them with `|` and pass values
VTE adds itself (`PCRE2_UTF`), and the four groups (compile, extra, JIT, match) reuse the same
bits. Tests compare each helper with the loaded library's signals and each constant with
`pcre2.h`.

## 7. Parameters are single objects unless declared

runic 0.8 writes `[^]T` for a pointer parameter whose C name ends in `s` (`settings`, `lines`),
however many elements it holds, which lets a caller index past one element, and drops a trailing
`va_list`, binding the procedure as `#c_vararg ..any`. Amber's runic fork (branch `amber-patched`)
has `parameters: declared`: with it every procedure parameter is `^T` (`T **` is `^^T`) unless
`arrays:` in the package's `rune.yml` lists it, chosen against the C headers, and a va_list
procedure is skipped. Struct members, variables and typedefs keep runic's name guess, and the
parameters of function-pointer types are plain `^T`: a limit of the fork, true in every binding.
Where a binding needs it, the `param_rules` table in `postprocess.sh` restores the `[^]` for
those parameters' real arrays, rewrites single-object struct members and corrects `T ***` outs;
a row that matches nothing fails the build. Rejected: rewriting the output in `postprocess.sh`,
which had to be told each parameter, matched `va_list` procedures by name pattern (it deleted
`list_store_insert_with_values` for containing `_va`) and was a second place to keep in step
with the headers. `scripts/check-generated.sh` stays as the guard that any regeneration, with
any runic, keeps the listed parameters right.
