# Patched bindings

The bindings are generated by runic (Amber's fork, branch `amber-patched`) from the C headers.
Regenerating overwrites hand fixes, so each is also pinned by a typed variable in the
package's `patched.odin`: a regeneration that drops a patch fails to compile there instead
of misbehaving at run time.

To regenerate, run `make generate`, re-apply every row below, and build the package.

## Generation rules

`scripts/postprocess.sh vte` applies these to `vte/vte.odin`. They are odin-gtk's rules,
trimmed to what runic produces from the staged headers.

| rule | reason |
|---|---|
| `^glib.char` becomes `cstring` | `gchar *` is a typedef'd char pointer, which runic leaves as a pointer to `char` |
| `TYPE_*`, `PTY_ERROR`, `REGEX_ERROR` of the form `` `(vte_foo_get_type ())` `` become `foo_get_type`-style names | macro text runic quotes as a string; `TYPE_FOO` then names `foo_get_type` |
| `MAJOR_VERSION`, `MINOR_VERSION`, `MICRO_VERSION` lose their backticks and parentheses | the version test reads them as numbers |
| `SPAWN_NO_*`, `SPAWN_REQUIRE_SYSTEMD_SCOPE` and `REGEX_FLAGS_DEFAULT` become Odin expressions | C shifts, ORs and `u` suffixes runic quotes |
| `TEST_FLAGS_NONE` and `TEST_FLAGS_ALL` become `u64(0)` and `~u64(0)` | `0UL` and `~0UL` |
| `FeatureFlags.MASK` and `PropertyId._VTE_PROPERTY_ID_MAX` are dropped | `MASK` is the C value -1, which a `u64` enum cannot hold; the other is a private bound |
| `PtyFlags`, `UuidFormat`, `PropertyFlags` and `FeatureFlags` become `FooBit :: enum` of bit indices plus `Foo :: bit_set[FooBit; u32]` (`u64` for `FeatureFlags`); zero members and composites become constants of `Foo` (`PTY_DEFAULT`, `PROPERTY_FLAG_NONE`, `UUID_FORMAT_ANY`) | `{.NO_HELPER}` instead of u32 ORs; the size and bits are those of C; see DECISIONS §5 |
| `Foo :: _VteFoo` is deleted and `_VteFoo` becomes `Foo` | one name per struct |
| `CharAttributes` is declared by hand | the C struct has bit-fields, which runic reads as an unsupported type and binds as an empty struct |
| `termprops_changed_func_ptr_anon_*`: `props` is restored to `[^]i32`; `sed` in `postprocess.sh` | `parameters: declared` cannot list the parameters of a function-pointer type, so the counted `props` (with `n_props`) would come out `^i32` |

## Parameters: declared, not patched

`vte/rune.yml` sets `to.detect.parameters: declared`, so runic types every procedure parameter
`^T` (`^^T` for `T **`) unless `detect.arrays` lists it. The listed arrays are `fds` and
`map_fds` (`int const *` with a count) of `pty_spawn_with_fds_async` and
`terminal_spawn_with_fds_async`, `regexes` (`VteRegex **` with a count) of
`terminal_check_regex_array_at` and `terminal_check_regex_simple_at`, and `matches` (`char **`,
one string per regex) of the latter. Nothing is rewritten afterwards; `scripts/check-generated.sh`
lists the corrected parameters and fails `make lint` when one is `[^]` again.

## Hand-written code

`vte/helpers.odin` is written by hand, not patched into generated output: the typed
`connect_<signal>` helpers and the `PCRE2_*` constants (SPEC). Regeneration never writes it;
`vte/helpers_test.odin` compares it with the loaded library and with `pcre2.h`.

## `vte`

`rune.yml` keeps GTK, GDK, GSK, GLib, Cairo, Pango and Graphene types external (imported from
`gtk4:`, `glib:`, `cairo:`, `pango:` and `graphene:`), and ignores the `_*`, `*DEPRECATED*`
and `*AVAILABLE*` macros and the `GSK_TYPE_*`, `GTK_TYPE_*` and `GDK_TYPE_*` ones the GTK headers
bring in.

Pins, in `vte/patched.odin`: `patched_get_user_shell` and `patched_terminal_get_window_title`
(the `cstring` rule), `#assert`s on the size, alignment and bit-field offset of
`CharAttributes`, on `MAJOR_VERSION` and on `TEST_FLAGS_ALL`, `patched_type_terminal` (the
`TYPE_*` rule) and `patched_feature_flags` (a `FeatureFlags` set, which cannot hold the C mask).

One pin per parameter the `declared` config makes a single object, as `patched_pty_get_size`,
`patched_query_termprop`, `patched_terminal_check_regex_array_at`, `patched_terminal_get_text`,
`patched_terminal_set_font_options` and `patched_uuid_new_v5`. `scripts/check-generated.sh`
lists every corrected parameter and fails `make lint` when one is `[^]` again. VTE's headers
take no `va_list`, so no procedure is skipped.
